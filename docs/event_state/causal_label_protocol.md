# P1 因果标注对照实验：协议草案（未实现、未运行）

状态：**草案，待测试方评审**。评审通过前不写实现、不启动任何训练或 GPU 评测。本文是预先声明：数据、分组、指标和成功/失败标准在看到任何结果前写定。

## 1. 要回答的问题

在冻结的 Qwen3.5-4B 底座和独立的带条件门控头上，**把监督从“响应时间戳”换成“事件因果区间 + 从未发生的负样本流”**，能否让门控头学到“条件满足时触发一次、否则沉默”？

- 借鉴 MOSS-VL 的部分：每个事件标“证据出现时刻”和“失效时刻”；加入全程不该触发的流；要求恰好触发一次。
- 借鉴 Mage-VL 的部分：门控头与语言模型分离，挂在冻结特征上。P0 试点已经是这个结构，并且门控带条件文本，本实验沿用。
- 不借鉴的部分：两者的大规模预训练和数据合成流水线。我们做不了，也不声称复现。

这是机制对照实验，不是论文贡献声明，也不是物业告警产品指标。

## 2. 与 P0 试点的关系

| 项 | P0（`response-timing-pilot-v1`） | P1（本协议） |
|---|---|---|
| 变化的因素 | 头的结构（5 组），标签固定 | **标签构造**（4 组），头固定 |
| 底座与特征 | 原始 Qwen3.5-4B 冻结；每秒两帧；8×8 网格 | 相同，复用同一提取代码和模型指纹 |
| 监督 | JoyAI 响应时间戳：之前等待，之后 3 秒就绪 | 事件起止区间；负样本流 |
| 负样本 | 无完整正常时段 | 正常视频 + 错配规则 |
| 阈值 | 只在校准集选 | 相同 |

**头的选择（事先写定）：** 用 P0 开发集上“提前率 ≤ 5% 时未响应率最低”的非时钟头。若 P0 没有任何头在源视频聚类置信区间上优于纯时钟基线，则固定用 `temporal`（标准、参数匹配的因果 Transformer）。P1 不比较头的结构。

## 3. 运行前的三道门（均不占 GPU）

任何一道不通过，就先报告，不进入 GPU 阶段。

**G1 数据与许可审计**
- 主机上确认存在：UCA 的 Train/Val/Test JSON、UCF-Crime 原始视频、UCF-Crime 官方异常检测测试列表及其时间标注。
- 核对 UCA 各划分与 UCF-Crime 官方测试列表的视频重叠。**凡在官方测试列表中的视频，一律不进训练和校准**，不论它在 UCA 的哪个划分。
- 记录 UCA 仓库和 UCF-Crime 的许可与使用条款；不明确的按“仅研究使用、不再分发”处理并写明。
- 输出：每个划分的视频数、句子数、事件时长分布、正常视频总时长。

**G2 起点偏差抽查（100 条）**
- 从 UCA 训练划分按固定种子抽 100 条句子，人工看片，记录“标注起点”与“证据最早可见时刻”的差。
- 通过标准：偏差绝对值的中位数 ≤ 2 秒，且 90% 的样本 ≤ 5 秒。
- 不通过时的预定处理：命中窗口从 10 秒放宽到 20 秒并在报告中注明；若中位数 > 5 秒，则停止，UCA 区间不能当作因果起点使用。

**G3 P0 报告已出**，用于按第 2 节的规则选头。

## 4. 数据构造

**规则文本。** 每条 UCA 句子生成一条监控规则，模板固定：“当画面中出现以下情况时提醒：{句子}”。规则文本不含时间信息。

**轨迹。** 沿用 P0 的窗口限制：每条轨迹最长等待 120 秒。规则在 t0 时刻注册，t0 在事件起点 a 之前按固定种子均匀采样，提前量在 5 到 120 秒之间。

**划分（按源视频，先划分再构造轨迹）。**

| 划分 | 来源 | 用途 |
|---|---|---|
| 训练 | UCA 训练划分中不在官方测试列表的视频；UCF-Crime 训练用正常视频 | 训练门控头 |
| 校准 | UCA 验证划分中不在官方测试列表的视频 + 一部分正常视频 | 只用于选阈值 |
| 开发（主结论） | 从训练来源中按视频哈希预先留出的 15%，训练不可见 | 报告主指标，只评一次 |
| 外部参考（不设门） | UCF-Crime 官方测试列表，类别级区间，规则为类别名 | 规则风格迁移的次要结果 |

**规模上限。** 缓存画面总时长不超过 40 小时（P0 实测特征缓存约 1.18 GB 每视频小时，即约 47 GB）。开发集至少含 4 小时正常画面。超出上限时按视频哈希固定抽样，不看标签内容。

## 5. 分组：只变标签

所有组用同一批视频、同一批规则、同一份特征缓存、同一个头、同一损失和同一训练预算。

| 组 | 正样本轨迹的标签 | 负样本流 | 检验什么 |
|---|---|---|---|
| **B 因果区间**（候选） | a 之前等待；[a, a+3 秒] 就绪；事件结束 b 之后恢复等待 | 有 | 完整方案 |
| **C 起点平移** | 同 B，但 a 随机前移或后移 5 到 30 秒 | 有 | 起点时刻是否真的被学到 |
| **D 无负样本流** | 同 B | 无 | “从未发生”的样本是否必要 |
| **E 视频级弱标签** | 规则对应事件所在的整条轨迹全部就绪 | 有 | 因果区间相对弱监督的增益 |
| 时钟基线 | 同 B，头只看经过的时间 | 有 | 计时捷径 |
| B-bce | 同 B，损失换成 P0 的类别均衡 BCE | 有 | 与 P0 损失对齐的参照 |
| 参照行（不训练） | P0 用 JoyAI 标签训练出的同一个头，直接在本开发集上评测 | — | 响应时间戳监督能迁移多少；数据来源不同，不作单变量结论 |

**负样本流的构造。** 占训练轨迹的 30%，两类各半：
- 正常视频上配一条来自其他视频的规则；
- 同一视频中事件发生之前、在 a 之前截断的片段。

MOSS-VL 的该比例是 5.1%；监控场景绝大多数时间无事发生，所以取更高比例。30% 是事先写定的值，不调。

**损失（除 B-bce 外各组相同）。** 逐步二分类交叉熵，乘以 focal 因子（γ=2）和按全局批次统计的逆频率类别系数，即 MOSS-VL 的状态 token 加权方式在二分类头上的对应形式。

**训练预算。** 与 P0 相同：每组最多 5 轮或 2000 次更新；取最后一个检查点，不挑开发集最高点。种子 7 为主结论；另跑种子 11 和 23 只报告离散程度。

## 6. 指标

**触发的定义。** 分数从低于阈值升到高于阈值算一次触发；一条轨迹可以有多次触发。

**阈值。** 只在校准集上选：使负样本流上的误触发率不超过 **每规则流小时 1 次**。开发集固定该阈值。

| 指标 | 定义 |
|---|---|
| **事件召回（主指标）** | 首次触发落在 [a, min(b, a+10 秒)] 内的正样本轨迹比例 |
| 提前率 | 首次触发早于 a 的比例 |
| 未触发率 | 整条轨迹没有触发的比例 |
| 延迟 | 命中轨迹上“首次触发 − a”的中位数和 95 分位 |
| 重复触发 | 每条命中轨迹在首次触发之后的额外触发次数均值 |
| 误触发率 | 开发集负样本流上每规则流小时的触发次数 |

**“每规则流小时”不是“每摄像头小时”。** 一路摄像头同时挂 K 条规则时，每摄像头小时的误触发约为 K 倍。开发集只有约 4 小时正常画面，低于约每小时 0.25 次的误触发率无法可靠测量。报告中两点都写明。

**置信区间。** 按源视频聚类 bootstrap，4000 次，种子 7，与此前实验相同的分位约定。

**探针。** 对 B 组做零视频和打乱规则文本两项探针，与 P0 相同。

## 7. 事先写定的判定

主结论只看种子 7、开发集、上述阈值。

**成立（因果标注在此规模下有用）需同时满足：**
1. B 的事件召回比 E 高至少 5 个百分点，置信区间下界 > 0；
2. B 的事件召回高于 C，置信区间下界 > 0；
3. B 的事件召回高于时钟基线，置信区间下界 > 0；
4. 两项探针都使 B 的事件召回至少降一半；
5. B 在开发集负样本流上的实测误触发率不超过每规则流小时 2 次（校准目标的两倍以内）。

**不成立：** 第 1 条不满足。结论是“在本数据规模和冻结特征上，因果区间标注相对弱标签没有可测增益”，停止这条线，不靠加数据或加训练时长挽救。

**无结论：** 第 1 条满足但 2 到 5 中有不满足的。按不满足的条目报告原因（例如只学到计时、不看画面、阈值不迁移），不作正面声明。

**无效：** 覆盖不完整、指纹不一致或任一道门未通过。

D 组和 B-bce 只作描述，不参与判定。三个种子的结果若方向不一致，在报告首段写明。

## 8. 这个实验不能说明什么

- 不能说明零样本规则（训练中没见过的表述或事件类型）是否可用；外部参考行只给出初步迹象。
- 不能给出物业部署意义上的误报率：正常画面只有几小时，且全部来自 UCF-Crime。
- 不涉及触发后生成描述、边生成边感知、长于 120 秒的等待或跨小时的流。
- 冻结底座：不能说明联合训练底座会怎样。
- 单一数据集：跨数据集效果未检验。异常检测方法跨数据集退化到接近随机是已有报道的常态。
