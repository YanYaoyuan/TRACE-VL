# P1 证据时间标注对照实验：协议草案 v2（未实现、未运行）

状态：**草案 v2；第 10 节事项已定，第 1 步（100 条标注可行性检查）的 CPU 工具已实现**。正式训练数据规模和主实验是否按 A/B/T 执行，等抽查结果和 P0 报告再定。v1（提交 `3094a76`）按原始 UCA 区间直接构造标签；v2 按评审意见改为“前缀可验证的证据充分时间”，并把标签与损失解耦。锁定前不写实现、不启动任何训练或 GPU 评测。

## 1. 只回答一个问题

固定 Qwen3.5-4B、特征、预测头和训练预算后：把**原始动作时间标注**换成**经过核验的证据充分时间**，能否改善响应时机，并超过只看时间的基线？

本轮不证明长期记忆有效，不声称复现 MOSS-VL，不是论文贡献声明。只有标签收益可信后，才考虑加记忆或换架构。

## 2. 预测目标：证据状态，不直接预测是否发言

模型输出“当前可见证据是否足以支持指定规则”。

| 状态 | 含义 |
|---|---|
| NOT_READY | 条件尚未满足，或有证据表明状态已结束 |
| READY | 条件满足且状态持续 |
| UNKNOWN | 被遮挡或证据不够。**UNKNOWN 不是 NOT_READY** |

首次告警、去重和解除由所有组共用的一套外部规则处理（第 7 节）。这样把“模型是否识别出条件成立”和“系统是否已经提醒过”分开。以后若直接训练 silence/response，再把“已发言”的历史放进模型输入。

**P1 的实现方式（待确认，见第 10 节问题 3）：** 头仍是二分类（READY 对 NOT_READY）；UNKNOWN 区间不参与损失和计分。不在本轮加三分类输出，以免同时改标签和输出空间。

## 3. 标注协议

每条“视频 + 规则”记录：

| 字段 | 含义 |
|---|---|
| `event_start` | 相关动作或状态开始的时间（原始标注） |
| `evidence_ready` | 只看截至当前的画面，首次足以确认整条规则成立的时间 |
| `valid_end` | 有证据表明状态不再成立的时间；无法判断时留空 |
| `uncertain_intervals` | 遮挡、证据不足或边界不明确的区间 |
| `evidence_note` | 判断依据 |
| `negative_type` | 从未发生 / 尚未发生 / 视觉相似但关键条件缺失 |

**历史事实类规则**（例如“曾经有人拿过包”）没有清楚的结束语义：不编造 `valid_end`，本轮只评首次响应。

**前缀核验：**
1. 可以先参考完整视频生成候选标签。
2. 确认 `evidence_ready` 时，只给审核者看截至候选时刻的画面，不展示后续视频和完整字幕。
3. 再检查更早的时间是否已有足够证据，避免标晚。
4. 看不准的边界记为区间（例如 17～19 秒），该区间不参与损失和计分。

**规则范围：** 优先选能直接从画面判断的动作和状态。意图、身份、所有权，以及没拆开的复合句，不作为主实验规则。

## 4. 划分与负样本

先按源视频及可能的同源录像分组，再生成片段、规则和负例。

| 划分 | 比例 | 用途 |
|---|---|---|
| 训练 | 70% | 训练头 |
| 阈值校准 | 15% | 只用于选阈值 |
| 内部留出测试 | 15% | 主结论 |
| UCF-Crime 官方测试集 | 锁定 | 不参与训练、调阈值或改方案；最后单独报告，不与内部测试结果混合 |

比例可在看到任何结果前按实际样本量调整，确定后锁定。同一源视频及其衍生片段不跨集合。

**负例必须针对具体规则核验**，分三类：整段从未满足；当前尚未满足但未来可能发生；画面相似但缺关键条件。普通正常视频**不能**自动视为所有规则的负例。

负轨迹占 30% 作为第一轮固定起点，不当作最优比例。同时记录负轨迹数量、负视频小时数、正负有效帧比例。

## 5. 四组主实验

所有组固定相同骨干、预测头、视觉输入、规则、训练步数和告警策略。**损失统一用 P0 的类别均衡 BCE**，不同时改标签和损失。

| 组 | 训练标签 | 检验什么 |
|---|---|---|
| **A 原始时间** | 原始 UCA 区间构造状态标签；核验过的负流 | 对照 |
| **B 证据时间** | 同一批视频和规则，起止改为核验后的 `evidence_ready` / `valid_end` | **B 对 A 是主比较** |
| **C 无完整负流** | 同 B，但只保留正视频中事件前的自然等待帧 | 完整负流是否有帮助；控制或记录正样本曝光次数 |
| **T 时间基线** | B 的标签；只输入规则和已过去的时间，不输入视觉 | 时间先验能解释多少 |

- **所有组都用核验后的证据标签评测**，包括 A。
- P0 的 JoyAI 头直接测一次，放在“迁移参考”，不当严格对照。
- focal loss 不与新标签绑定。B 对 A 有可信收益后，再单独比较 BCE 与 focal。

## 6. 探针：模型是否看了视频、理解了规则

先做评估探针，不为每项重新训练：
- 用同长度的真实错配视频替换原视频；
- 同一段视频搭配不同条件的规则；
- 改变事件出现时间和等待长度，并重新核验标签；
- 全零视频只作补充，不能单独当作视觉依赖的证据（全零输入远离真实分布）。

v1 的“标签随机平移”保留为附加对照：它只说明时间标签对齐是否有影响，不单独证明因果理解。

## 7. 统一告警规则与阈值

所有组完全一致：
- 连续两个有效采样点高于阈值，触发一次；
- 已触发期间不重复告警；
- 连续两个有效采样点低于阈值后解除，之后可再次触发；
- UNKNOWN 或无有效观测时，不自动解除。

记录实际采样 FPS。同时保留**未经该策略处理的原始分数指标**，避免后处理掩盖模型差异。

**阈值只在校准集选：**
1. 筛出完整负流误报不超过 1 次/规则流小时的阈值；
2. 其中选事件召回最高的；
3. 锁定后再评内部测试集。

“规则流小时”不是“摄像头小时”。同一路画面挂多条规则时，另行统计聚合后的摄像头告警率。

## 8. 指标

- 证据充分后 1、3、5、10 秒内的事件召回率；
- 提前触发率（`evidence_ready` 之前触发）；
- 完整负流误报次数/规则流小时；
- 全视频流中事件之外的误报；
- 首次正确告警延迟的中位数和 95 分位，漏报率单独报告；
- 重复告警率；
- 有效帧 PR-AUC，以及 UNKNOWN 区间占比。

一条告警最多匹配一个事件。同一事件首次正确告警之外的触发，按预先定义计为重复或误报。

统计按源视频聚类，不把帧当独立样本。正式主比较至少 3 个固定种子，逐个报告。约 4 小时正常视频只能做早期诊断：即使观察到 0 次误报，也不能说真实误报率为 0。

## 9. 执行顺序与停止条件

**第 1 步：100 条标注可行性检查（不占 GPU）**
- 覆盖简单动作、持续状态、复合句和负例。
- 至少 30 条由两人独立核验。
- 记录：时间分歧、无法判断的比例、排除原因、**`evidence_ready` 与原始起点之差的分布**。
- 大量规则无法确定 `evidence_ready` 时，先调整规则，不开始训练。

**第 2 步：小规模冒烟测试**
- A / B / T 各一个种子。
- 检查因果 mask、输入是否含未来帧或视频总长度、标签边界和计数逻辑。
- 只检查流程，不挑结果作结论。

**第 3 步：锁定配置后跑正式主实验**
- 比较 B 和 A，并看 B 是否超过 T。
- 5 个百分点召回提升作为有实际意义的目标，同时看误报约束、置信区间、类别差异和各种子。

| 结果 | 处理 |
|---|---|
| 稳定提升 | 用第二种预测头复核关键 A/B 对照，再考虑扩数据 |
| 无明显提升且置信区间窄 | 暂停扩展，检查标签质量、冻结特征和任务本身 |
| 置信区间很宽 | 结论是样本不足，不宣称方案无效；优先补测试样本或提高标注一致性 |

## 10. 已定事项（2026-11-12 评审答复）

1. **标注投入。** 先分层抽 100 条，不预先承诺几千条全人工。
   - 校准集和测试集的关键时间边界由人工前缀核验。
   - 训练集先用模型生成候选时间，再抽样人工核验；记录通过率、提前和延后的误差、无法判断的比例。
   - 自动标注质量不足时，**不称其为“已核验的证据标签”**；先用小规模人工核验的训练集做探索，再决定是否扩大。
   - 100 条中至少 30 条由两人独立检查。扩大规模等看到质量和耗时再定。
2. **A 和 B 用完全相同的样本。** 相同的视频、规则和样本集合，只改时间标签。B 因核验不通过而剔除的样本，A 也同样剔除；被剔除的比例和原因单独报告。
3. **A/B 是否值得做，不用单一门槛决定。** “80% 相差不到 2 秒”只作提醒。先统计：差异分布、原始标签早于证据的比例、差异大的规则类型及其占比。差异确实很小且难例极少时，降低 A/B 的优先级，重点转向可靠负例和状态结束时间；仍保留小规模诊断结果，不直接认定“原始标注已经足够好”。
4. **UNKNOWN 首轮是标注与评估掩码**，不加输出类别。这些区间不参与损失和逐帧计分，单独报告占比。无有效观测时后处理不自动解除告警。这**不代表模型学会了识别 UNKNOWN**，只是它在这些区间没有被评判。
5. **规则来源。** 两类分开统计，不混成一个同质数据集：
   - 主线：从 UCA 句子改写成可观察、可核验的规则，复合句先拆解。
   - 补充试标：少量人工编写的持续状态规则，只检查“状态成立、遮挡、结束”能否被可靠标注，不当作已有的大规模训练数据。
   - 带时长的规则（例如“无人看管超过 30 秒”）只有在画面、可见范围和连续时长足以支持时才能标。不能凭一句 UCA 描述就假设具备这些标签。
6. **1 秒内召回** 保留但注明测量限制：每秒一步且连续两点触发时，后处理本身带来约一个采样间隔的延迟，再叠加采样对齐误差。它不作唯一主指标；同时报告不去抖的原始分数结果、3 / 5 / 10 秒召回和实际延迟。
7. **预测头** 按原规则固定一个：P0 有通过时间基线的非时钟头就选它，否则固定因果 Transformer。选择规则在看 P1 测试结果之前锁定。P0 报告未到不阻塞标注检查。

## 10a. 第 1 步的工具与交付物（已实现，仅 CPU）

工具在 `src/trace_vl/event_state/annotation.py`，操作脚本 `scripts/run_p1_feasibility.sh`，测试 `tests/test_event_state_annotation.py`。不含任何训练或模型代码。

| 命令 | 作用 |
|---|---|
| `sample` | 从 UCA 分层抽样，排除 UCF-Crime 官方测试列表中的视频，每个视频最多一条；生成两份空白标注表（第二份只含双人核验的 30 条） |
| `export-prefix` | 为每条样本导出**在候选时刻结束**的片段，另加提前 2 秒和 4 秒的片段；重新编码，无音频，不含之后的任何一帧；文件名是哈希，不透露时间；时间对照表与片段分开存放 |
| `validate` | 按记录格式检查填好的标注 |
| `report` | 决定分布与排除原因、证据时间与原始起点之差的**大小和方向**（总体与分层）、差异最大的 10 条、双人一致性、耗时 |

**默认分层（100 条）：** 简单动作 35、状态类 20、复合句 25、“尚未发生”负例候选 10、“同类别错配视频”负例候选 10。分层用关键词粗分，只为让样本覆盖不同类型，不是标签；负例候选必须由标注者按规则确认类型。

**标注流程：**
1. 标注者看完整视频，把 `rule_draft` 改写成可观察的 `rule`，填 `candidate_ready`。无法改写成可观察规则的，标 `excluded` 并写原因。
2. 运行 `prefix` 步骤，按 `candidate_ready` 导出前缀片段。
3. 标注者**只看前缀片段**确认 `evidence_ready`，并看更早的片段确认没有标晚；填 `prefix_checked` 和 `earlier_checked`。边界看不准时填区间。
4. 填 `valid_end`（无法判断留空；历史事实类规则不填）、`uncertain_intervals`、`evidence_note`、`seconds_spent`。

**交付物：** 规则清单（标注表中的 `rule`）、前缀核验记录、`feasibility-report.json`（含时间差分布和耗时）。

**对 UCA 数据的两点观察**（来自已固定版本的验证集 JSON，379 个视频、3,534 句）：
- 句子多为多从句的长描述，并常带主观推断（例如“seemed to be scolding”）。大部分需要拆解和改写才能成为可核验的规则，改写本身是标注工作量的一部分。
- UCA 也标注了正常视频（验证集 379 个中有 217 个）。这些句子描述的是日常活动，可用作“规则成立但不是异常”的样本，也再次说明正常视频不能直接当负例。

## 11. 本实验不能说明什么

- 不能给出物业部署意义上的误报率：正常画面只有几小时，且来自单一数据集。
- 不能说明训练中没见过的规则表述或事件类型是否可用。
- 不涉及触发后生成描述、边生成边感知、长于 120 秒的等待或跨小时的流。
- 冻结底座：不能说明联合训练底座会怎样。

## 12. 锁定后的实现清单

1. 标注记录格式与校验器（第 3 节字段；区间合法性；历史事实类规则不带 `valid_end`）。
2. 前缀核验用的片段导出工具：只导出截至候选时刻的画面。
3. 数据适配器：按源视频分组划分；A / B / C / T 四种标签构造；UNKNOWN 掩码；负例三类。
4. 共用告警策略、阈值选择（只读校准集）和第 8 节指标；原始分数指标并行输出。
5. CPU 测试：划分无泄漏、标签边界、掩码、触发与解除计数、一告警一事件匹配、阈值不读测试集、输入不含未来帧或视频总长度。
6. 探针评测（错配视频、换规则、改变事件时间）。
7. 一个固定代码版本的 A100 启动器：测试 → 数据核验 → 特征 → 冒烟 → 正式 → 报告。
