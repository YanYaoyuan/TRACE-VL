# TRACE-VL 流式视觉编码

TRACE-VL 的研究目标是训练一个原生流式视频 VLM。新视频持续更新模型内部的视觉状态，
语言解码器读取当前画面和历史证据。以 Qwen3.5-4B 为初始化，四张 A100 负责实验。
第一阶段直接改写视觉塔的计算路径，控制语言端变量。

## 架构

Qwen 的浅层视觉块处理当前的两帧时间块。全景特征给出两个信号：对比区域上次刷新的
浅层特征选择需要更新的位置，汇总当前浅层特征为上下文。每个位置是 Qwen 合并前的一组
完整空间 patch。上层 ViT 只对入选位置计算 Q/K/V、注意力输出和 MLP，并使用固定大小的
全图 K/V 状态。起始、镜头切换和定期刷新时走原生上层块。镜头切换使用相邻两步全局
浅层特征的余弦距离。

对每个未刷新位置，从上次深层特征出发，将当前全局上下文与当时上下文的差异投影到
低维空间，用该位置的浅层特征调节系数，再映射回 Qwen 合并后的视觉 token。校正器初始
输出为零。它生成给 LM 的特征，刷新计划和 ViT K/V 更新规则与直接复用组相同。
后续阶段将独立的视觉状态与有限历史接入语言解码器的交叉注意力，再做联合 QA 训练。

[微软 Mage-VL](https://arxiv.org/html/2607.24904) 提供了 codec 驱动的区域编码思路。
[MOSS-VL](https://arxiv.org/html/2608.15045) 提供了独立视觉缓存的参照。
[STC-Cacher](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_Accelerating_Streaming_Video_Large_Language_Models_via_Hierarchical_Token_Compression_CVPR_2026_paper.html)
也使用上层稀疏计算与缓存，核心实验对应的结构差异是对每个复用位置校正其上次刷新后的
全局语义变化。

## 本轮实验

用 40K 混合清单内的 LLaVA 通用训练片段，固定种子按来源抽取 512 路片段，训练 2 遍。
训练冻结 Qwen 权重，4 卡 DDP 只拟合校正器。刷新比例在 25% 与 50% 间交替。
教师为相同帧的 Qwen 全量视觉特征。目标是各复用位置的归一化特征均方误差。
训练的视觉蒸馏路径只读取视频和时间。已准备的 OVO 和 StreamingBench 不参与训练样本选择，
并按可获得的来源标识排除交叉媒体。

评测共五组，即原生全量、25% 和 50% 的直接复用与校正。同一问题先解码一次可见画面，
五组共享帧和 prompt。默认在视频时钟上以 2 fps 采样，最多回放 16 个时间块，最近 8 个交给
原生 Qwen 问答路径。每题独立回放，所有帧时间戳均不晚于问题。首步全量、定期刷新和切镜
都会增加实测刷新率。使用预先准备的 OVO 选择题开发集，以及官方 StreamingBench
实时视觉选择题中按视频轮转取的 250 题。[StreamingBench 官方协议](https://github.com/THUNLP-MT/StreamingBench)

主要对照是同一刷新比例的校正减直接复用，报按视频配对的 95% 区间、相对全量的精度差、
OCR/实时分项、归一化特征误差和实测刷新率。时间拆成纯视觉单步、视觉加一次作答、
含解码与处理的最近片段回放服务成本。编码器帧率独立记录。当前短回放和单 token
计分面向开发，正式比较需要持续在线流、长时间运行和官方评测协议。

推进完整架构的依据是同一刷新比例下校正改善 QA 与特征误差，同时仍比逐步全量编码更快。
额外查看 OCR 和实时子集的绝对变化。只有单种随机种子的点估计时，结论局限在开发诊断。
若校正无法改善等预算下的精度—延迟曲线，结束当前全局校正假设，保留全量和直接复用的结果。

## A100

脚本从固定 Git 提交建立代码快照。对照复用服务器已有的权重、清单和视频。它按选中样本从
StreamingBench 的 ZIP 补解压，训练后自动完成五组评测，写出 `REPORT.md`、
`report.json`、训练曲线 JSONL、逐题记录和 `reports.tar.gz`。重新运行同一提交与配置会恢复
已保存的训练进度并跳过完成题目。日志在实验目录的 `logs/`。

`TRACE_TRAIN_MANIFEST`、`TRACE_OVO_MANIFEST`、`TRACE_STREAMING_ROOT` 和 `TRACE_MODEL`
可以覆盖默认路径。`TRACE_STREAMING_ROOT=` 可以只跑 OVO，使用另一实验目录。
`TRACE_OUT` 可指定 NAS 输出。`TRACE_PREPARE_ONLY=1` 跑数据准备。

### 续跑已训练的评测

启动时设置 `TRACE_RESUME_RUN` 指向原实验目录。入口校验原始清单、基础模型、校正权重和
已有逐题记录，并执行剩余评测与汇总。修复使用独立的评测源码快照及
`eval-recovery.json`，原训练源码继续保留。

评测默认每卡两个解码线程。各分片共享原始帧时间戳索引，探测或解码超时的视频按需复制到
A100 本机 `/data` 下的缓存后重试。可用 `TRACE_EVAL_SCRATCH` 指定缓存路径，或设置
`TRACE_EVAL_DECODE_WORKERS` 调整每卡并行度。由于续跑前后的解码开销不同，报告提供分流程
回放时延。模型对照使用同样的帧选择、五路输入和分项计分。
