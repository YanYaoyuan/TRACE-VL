# 核心视频模型：外部迁移与下一阶段受控训练（2026-11-14）

主线是视频特征进入语言模型后的问答理解能力。此队列不训练告警头，不训练旧 Stage-2 的拼接长流／记忆淘汰配方。当前底座是 Qwen3.5-4B；这里的“下一阶段”是核心 QA 的继续训练，不是历史项目中名为 Stage-2 的实验。

## 已有证据

用户提供的 `core-qa-8c5e1b7-001/summary.json`：同源开发集 2,415 题、607 个视频，一次训练随机种子。严格生成单字母计分：原始 full 62.11%，原始 grid 51.14%，训练后 full 93.25%，训练后 grid 91.59%。grid 训练增益 +40.46 pp；训练后的 grid 比 full 低 1.66 pp。

这支持继续验证，但不是外部迁移、模型结构创新或论文 benchmark 成绩的证明。生成格式的改变也可能贡献涨分，下一轮单独测量它。

## 冻结的外部验证

四组保持同一底座、同一视频、同一 16 帧、相同提示和时间戳处理：原始 full／原始 grid／已训练 full／已训练 grid。只读固定第 1,000 步权重，不选择最佳 checkpoint。

| 数据 | 固定范围 | 主指标 | 不退化检查 |
|---|---|---|---|
| OVO | 以 `ovo-transfer-cdbac0c-001/transfer` 的 688 题、260 视频为候选；检查诊断半区归属与清单哈希，再按下述因果帧数规则固定实际清单 | 候选 EPM/ASI/HLD 305 题；实际纳入数量由 inventory.json 报告，按题加权准确率 | 六项实时感知任务 |
| NExT-QA | 官方 val.csv，以 seed=17 对视频 ID 哈希排序取 200 视频，保留其全部问题：1,744 题 | TN/TP/TC 共 555 题、181 视频；包含先后关系和时间定位 | DC/DL/DO 描述性问题；因果 CW/CH 另报 |

NExT-QA [官方数据](https://github.com/doc-doc/NExT-QA/blob/main/dataset/nextqa/val.csv) SHA256 固定为 `43198bdef8436b8d64a9b75d846b0987c10cbf94ebf4be325c4a4e54634d66b8`。任务归类参考[官方评测代码](https://github.com/doc-doc/NExT-QA/blob/main/eval_mc.py)。此处合并 TP/TN/TC 为时间任务，并不声称报告完整官方总分。

OVO 每题只采样提问时刻之前的帧；NExT-QA 按离线任务读取整个视频。两者都从新模型状态回答，每视频等距采样 16 帧；因此这里是迁移诊断，**不是此前 FIFO 流式协议，也不是 Mage-VL 四帧协议复现**。两组可用相同帧而不具有相同计算量，full/grid 的 token 差异如实保留。

### A100 数据适用性修复：短前缀

首轮已通过 460 个视频完整解码，但在 `ovo-420` 发现提问前不足 16 张不同帧，尚未产生任何模型分数。保留原有固定 16 帧采样：提问时间早于第 16 帧实际 PTS 的题目统一排除；恰好等于该 PTS 的题目保留。不补未来帧、不重复帧、不换题。选择仅依赖媒体时间戳，在所有模型运行前完成，所有对照和后续训练后的评测共用这一份清单。

`exclusions.json` 保存每道排除题的 ID、任务、视频、提问时间及第 16 帧时间；`inventory.json` 保存候选数、实际数和分任务排除数。样本量与聚类数量要求在排除后重新检查，不降低门槛。外部结果属于这个协议的可用子集，不能继续标为完整 688 题分数，也不能与旧 688 题结果直接作配对比较。后续如要覆盖这些短前缀，须另立统一短前缀协议。

主计分采用第一次答案位置中选项字母 A/B/C/... 的最高 logit，不输入正确选项；另外记录原先的严格自由生成分数及格式合规率。这样能看出是否只学会按格式输出。该选择分数仍受选项字母/顺序偏差影响，不是完整候选答案似然。

每个差值按源视频聚类 bootstrap 4,000 次（seed=7），报告 95% 区间。精确相同视频字节合并为同一聚类。数据准备检查训练集源 ID/别名及视频 SHA256 重叠；不把这叫作感知去重或基础模型预训练污染审计。

**事先固定的继续训练条件**：已训练 grid 相对原始 grid，在 OVO 历史追溯与 NExT-QA 时间任务上均至少 +2 pp，且区间下界 >0；两边不退化检查的下界均 >−2 pp。任一未达标就产出完整报告并暂停后续训练，不修改阈值或追加种子直到通过。区间过宽也可能导致未达标，不能都解释成负收益。其他对比是诊断，不替代这两个主指标。

不读取 OVO 最终半区作评测，不打开 NExT-QA test.csv；这些外部问题均不用于梯度训练。已经用过的 OVO 诊断半区与 NExT-QA val 都是开发用途，不能写成从未使用过的最终测试。

## 下一阶段：两组 300 步核心 QA 训练

外部检查通过后，自动顺序运行：

1. `continued_grid`：从本轮 grid 第 1,000 步继续训练 LoRA。
2. `temporal_grid`（T0）：同一个初始化，增加直接连接到 LM 视觉输入的因果时间适配器，并联合训练它和 LoRA。

T0 路径：冻结视觉编码器 → 每帧固定 4×5 池化 → 每个空间格沿时间做两层 128 维因果 Transformer → 残差回写视觉 token → 原语言模型。时间编码来自实际采样帧时间；零输出投影保证初始视觉表示不变。问答答案 CE 同时训练新模块与 LM LoRA；不是外接分类头。普通时间 Transformer 仅作为 T0 对照，不能预先称作新的论文贡献。

两组使用相同原训练清单、问题抽样 seed=17、4 卡×梯度累积 4、300 次更新、LoRA rank=8、初始学习率 2e−5（余弦到 0.1 倍），不增添训练数据、不改变帧数和 token 预算。新模块有额外参数/计算，只有样本、更新次数与 LM token 预算匹配，并非完全相同 FLOPs。各先运行 2 步独立流程检查并重载评测，再从相同父权重重新开始正式 300 步；flow 权重不进入正式训练。

固定最终第 300 步复测内部、OVO、NExT-QA，同时对比 T0−继续训练基线、两者−继续训练前的 grid。不会仅凭内部涨点自动扩大训练。如果时间任务确有外部收益，下一阶段才加入帧序打乱、去历史和等参数对照，检验收益是否依赖时序；本队列未把这些未完成消融算作证据。

## A100 一键队列

`scripts/launch_core_transfer_a100.sh`，必须传入已测试代码的 `TRACE_REV`。它创建固定源码快照，不切换现有工作目录，不修改旧结果；沿用 UV 环境。默认复用：

- `/nas-data/vlm/yyy/tracevl-runs/core-qa-8c5e1b7-001`
- `/nas-data/vlm/models/qwen3.5_4b`
- 已有 OVO 清单及视频
- `/nas-data/vlm/data/NExTQA` 与四个 `llava/*_nextqa` 目录内的视频／压缩包

只补取不到 1 MB 的官方 val.csv（下载后核验 SHA256）；不下载模型或大型数据。只解压选中的缺失视频，保留原包，24/32 个 CPU 工作线程验证完整视频，8 个归档工作线程。源视频变化、缺失、歧义、完整解码失败、训练重叠均在 GPU 评测前报错，不改选一批更容易获得的数据。

`TRACE_OUT` 默认 `.../tracevl-runs/core-transfer-<代码前7位>-001`；`TRACE_DATA_OUT` 为对应 `.../tracevl-data/core-transfer-v1-<代码前7位>`。进程锁、源码/配置/模型/清单哈希和原子结果文件保证重复启动检查身份后继续。`TRACE_PREPARE_ONLY=1` 只准备数据。

`TRACE_REUSE_PREPARATION` 可指向先前中断的数据准备目录（不是实验结果目录）。检查实验/数据设置一致后，只复用已有视频及 SHA256 一致的完整解码缓存；在新目录重新生成输入身份、适用性排除和冻结清单，不复制旧结果或完成标记。此前失败目录保留。

产出 `transfer-report.json`、`queue-status.json`，通过后还有 `next-stage-report.json`；各组逐题预测、训练指标、检查点和分片日志均保留。自动生成 `reports.tar.gz`（报告/清单/预测/日志，不含模型与视频）。主启动日志保存在用户的重定向位置。
