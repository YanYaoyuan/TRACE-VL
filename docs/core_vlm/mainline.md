# TRACE-VL 核心模型主线（2026-11-13）

用户确认的目标：训练具有视频理解能力的 VL 模型，研究核心架构改进，最终与
**Mage-VL、MOSS-VL** 做有清楚协议说明的比较。物业摄像头是应用场景。
参数量不硬性限定 2B；本机双 5090 调试，4×A100-40GB 承担正式训练。

本文件替代此前把冻结 VLM 的告警头作为论文主线的计划。告警时机、harness、
记忆调度不能替代基础模型对动作、顺序、因果线索、状态变化及历史事实的理解。
后续实验的 QA 损失必须直接训练 VLM 的语言模型适配参数，并在架构实验中到达新增视觉模块。

## 已有证据决定什么

| 实验 | 能支持的结论 | 后续处理 |
|---|---|---|
| Transition / after / B4，pilot-003～005 | 当前 transition 实现没有胜过简单区域池化 | 保留 B4 为强基线，不把旧模块换个名字当创新 |
| Learned retention，等 KV 修复评测 | 年龄/惊讶度评分接近 FIFO，未取得预定增益 | 不继续扩大这一训练配方 |
| Stage-2 合成长流 | 内部开发流 FIFO 提升约 4.90 pp，但 OVO 开发集 backward 下降 4.92 pp | 不以内部涨点证明跨域视频理解提升 |
| Recent-window 对照 | fresh16 下 Stage-2 仍下降约 4.92 pp | 退化不能只归因于持续状态或淘汰策略；原因仍待证实 |
| Event-state P0（冻结 4B 的五种头） | event-state 97.16%，GRU 97.50%，clock 96.49%；zero-visual 98.83% | 响应时间标签存在捷径风险；不是基础模型理解能力证据，不自动推进 P1 |
| 原始 Qwen3.5-2B vs S1，同 B4/FIFO | A100 旧任务在 flow 阶段因并发 `run.json` 写入失败，尚无分数 | 已修复，重新评测两组；属于整个 Stage-1 包的对照，不分解 LoRA/CST |

历史结论限定在具体实现、数据和配方。它们不证明时序建模、内容记忆或长视频训练普遍无效。
保留实验记录与冻结的最终测试划分；不追求把负结果写成主论文。

## 模型与基线

新一轮以**原始 Qwen3.5-4B**为候选起点，已有 A100 本地权重可复用。
必须记录实际权重哈希和配置；旧 2B Stage-1 结果单列，不能充当 4B 的训练对照。
4B 是否适合目标帧数由真实显存与吞吐测试决定，不凭总显存相加推断。

| 组 | 模型路径与训练 | 回答的问题 |
|---|---|---|
| N0 | 原始 4B，官方原生视频处理/提示路径，无训练 | 底座原有能力是多少 |
| C0 | 原始 4B，统一实验输入路径，无训练；full/grid 分别记录 | 实验封装和压缩本身改变多少 |
| C1 | 同一个 4B、同一路径，完整视觉 token，视频 QA LoRA 训练 | 只用训练数据能获得多少提升 |
| C2 | 同一个 4B、固定区域池化，同数据同样本顺序、同 QA LoRA 配方 | 简单压缩后的强基线 |
| T0 | 普通因果时间模块 + C2；QA 联合训练 | 一般时序容量是否已足够 |
| T1 | 待确定的核心架构 + C2；QA 联合训练 | 在 T0/C2 之外的特定结构是否有效 |

N0 与 C0 不是同一条推理路径，均需实测。原始底座可以没有训练预算；架构归因比较的
C2/T0/T1 必须共享数据、起始权重、可训练 LoRA 层、训练轮数和选模规则。
报告新增参数、实际视觉 token、总输入 token、GPU 小时、峰值显存与端到端吞吐。
相同样本量、相同 token 数、相同 GPU 时间是不同约束，不能同时宣称完全相同。

**架构选择尚未锁定。** 优先调查“保留预训练外观表示、增加因果时序对应关系”的视觉到语言桥接，
服务于顺序和状态变化问答。它必须区别于已有 CST/普通 temporal adapter；
否则只能作为 T0。不能把零门控残差、时空 Transformer 或新增 query token 本身称为创新。
在确定 T1 前补齐最近方法的全文和官方实现比较，明确最接近方法、结构差异、监督来源与失败条件。
不因基线未完成而继续训练冻结底座的独立二分类头。

## 数据利用

“下载了很多”不等于“已具备可配对的视频 QA 训练集”。先按标注、原片、任务、划分建立索引；
只有对应真实原片且通过解码检查的样本进入共同训练清单。不扫描无关压缩包寻找不同来源的素材。

| 已有数据 | 当前用途 | 具体处理 |
|---|---|---|
| LLaVA-Video YouTube / academic，0–30 s、30–60 s、1–2 min、2–3 min | 核心视频 QA 训练首选 | 从题目对应路径建立归档索引，按固定清单解压；保留连续原视频、原始时间和来源 ID |
| FineVideo | 后续长视频训练候选 | 先审计原生标注能支持的 QA/时间监督，不把字幕自动当事件真值 |
| LLaVA 的 NExT-QA / PerceptionTest / ActivityNet 衍生数据 | 暂不直接混入 | 与拟用评测源视频排重；若保留该 benchmark，就隔离相应来源及同源改名版本 |
| OVO-Bench | 开发诊断与最终 streaming benchmark | 已处理全集不意味着能用全集训练；开发/最终划分维持原样 |
| StreamingBench、Video-MME | 外部视频理解评测 | 训练排除其源视频；官方任务汇总与本地子集结果分开 |
| NExT-QA | 时间关系诊断候选 | 先核对 split、可用标注和训练排重，再冻结主指标及视频清单 |
| JoyAI event_grounding | P0 历史记录 | 响应时间任务不能直接替代核心视频 QA；当前不继续扩大 P0 |
| UCF-Crime、CUVA、ShanghaiTech、XD-Violence、CCTV 等 | 后续监控应用验证 | 不因下载齐全就混入缺少 QA/事件监督的数据；用途另行记录 |

## 训练与验证顺序

1. 读完旧 2B base-control 结果，确认已有能力归属；不等待其结果才编写新核心训练路径。
2. 校验 4B 原生 N0 与统一路径 C0 的帧清单、提示、答案提取和真实输入数量。
3. 在本机跑 C1/C2 短训练：检查答案损失到 LM LoRA 的梯度、真实视频敏感性、保存/重载、
   双卡一致性，以及切换/删除视频对答案的影响。玩具梯度测试不能代替真实视频验证。
4. 首批训练用连续视频，先限制输入为 16/32 个实际采样帧并记录覆盖时长；
   bf16、冻结视觉编码器、LM LoRA、梯度检查点。LoRA rank、batch、累积步数在 profiling 后锁定。
   不直接恢复旧随机桥接或已退化 Stage-2 权重；暂不使用拼接不相关视频的长流配方。
5. 冻结 C2/T0/T1 的实验清单及主检验，再由一个 A100 脚本完成数据准备 → flow → 顺序实验 → 报告。
   必需输入缺失时给出来源和具体文件清单；不通过降低样本门槛或临时改 split 让任务过关。
6. 主检验比较 T1 与同数据训练的 C2 和 T0；仅在可归因增益成立后做 3 seeds、长视频扩展和最终 benchmark。

T1 的主时间理解任务、最小有意义增益及样本量，必须在 T1 运行前写入机器可读实验配置。
候选标准为 +2 pp 且视频簇配对区间下界 >0，并检查静态理解是否退化；尚未完成
数据可用性盘点，不能把这个候选数字冒充已冻结协议。区间宽意味着证据不足。
消融包括同数据无模块、普通 temporal 模块、打乱/逆转帧序、移除历史；
标签对帧序变换不再有效的样本只作为敏感性诊断，不能照搬原标签算准确率。

## 与论文比较的口径

本地阅读的 Mage-VL Table 7（PDF p.22）与 MOSS-VL Table 6（PDF p.13）不能混用总分：

| 报告 | OVO 汇总 | 输入/解释 |
|---|---|---|
| Mage-VL Table 7 | 6 项 RTVP 的均值与 3 项 BT 的均值再取平均，79.84 / 48.15 → 64.00 | 文中注明最近 4 帧、1 fps；不是我们旧 fresh4 的 8 帧 |
| MOSS-VL Table 6 | FAR / BT / RTVP 三类均值，62.1 / 72.6 / 75.9 → 70.2 | 模型原生 streaming 协议；不能拿不含 FAR 的分数直接排序 |
| 我们旧 688 题实验 | 自定义开发集、问题加权准确率，另报 task macro | 不是官方完整测试分数；只用于开发决策 |

外部比较同时保留两张表：官方/作者原生协议的可复现实测（与引用的论文分数区分），
以及共同输入预算的受控比较。后者须说明对各模型原生机制的改动。
Mage/MOSS 预训练数据量、参数量和计算不同；它们是外部参照，不是架构因果归因对照。
缺失任务、不同划分、不同帧数、字幕开关、计分与提示差异均需显式显示，不能空缺时重新平均。
