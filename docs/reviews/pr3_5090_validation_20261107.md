### [P1] Zero delta tokens cause extreme input-side gradients, even on short static clips

Location: [modules.py:258–259](https://github.com/YanYaoyuan/TRACE-VL/blob/143e4c6cb7a5bb9b88bbcfce7a69708cbccaf9a2/src/trace_vl/v3/modules.py#L258-L259).

For unchanged frames, `after - before` is zero. The correction head and type embeddings also start at zero, so the pretrained LM receives exactly zero delta embeddings.

A controlled real-backbone test on a 3 s static gray clip gave:

| Variant | Unclipped total gradient norm |
|---|---:|
| Original transition tokens; all emitted delta norms exactly 0 | **1.0385e12** |
| Diagnostic hook: add a detached after-token anchor to each delta, keeping its original gradient path | **13.70** |
| All I-steps | **4.35** |

The huge gradients concentrate in `transition.type_embed`, the delta head's final bias/weight, and `cst.gate`; LoRA gradients are orders of magnitude smaller. Setting `tbptt_steps=8` did not resolve the issue in the 120 s test. This is therefore not just a long-BPTT problem.

Please use a nonzero, appropriately scaled pretrained-feature anchor or another stable transition representation, and add a real-backbone static-input gradient regression check. Global clipping at 1 makes the step finish but can severely suppress updates to the other parameter groups. The anchor intervention is diagnostic evidence, not a completed model-design fix.
