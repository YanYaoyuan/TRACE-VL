# Endpoint reader training flow

`core_vlm.endpoint_reader.EndpointReaderEpisode` adds an answer-only LM LoRA update on disposable forks of the existing native hybrid stream. The live stream is question-blind and retains bounded KV plus the model's recurrent/conv state. This primitive supports the existing window/reservoir/full policies; it is not a full training launcher or a learned writer.

One source episode uses one set of parameter values. Build its complete visual prefix under `torch.no_grad`, not `inference_mode`. Seal the actual endpoint before presenting questions. Teacher forcing appends the question tail and preceding gold-answer tokens only on a disposable cache fork; prompt/visual tokens have no loss. Include the tokenizer's intended answer-termination token in the supplied answer IDs. Over-budget answers raise instead of being truncated silently.

The prefix state/KV is detached. Answer CE retains gradients to LM LoRA only; this is truncated reader adaptation, not full-prefix BPTT or training of the visual encoder/history writes. Existing `functional_linear_cache` updates prevent overwriting Gated DeltaNet states needed by backward. Snapshots check that question forwards do not mutate live KV/state/positions/owners or retention RNG.

`train_step` averages each question's mean-token CE within a source, accumulates its question gradients, clips them and performs exactly one optimizer update. The optimizer must own exactly the LoRA parameters; the model stays in eval mode with trainable LoRA for deterministic, dropout-free execution. The episode closes after an attempted update. Standard PyTorch parameter-version changes outside this API also invalidate cached prefixes. Rebuild the source prefix under the updated weights before another source episode; mixing stale keys/values with new LoRA is forbidden. Version checks do not claim detection of arbitrary unsafe external `.data` mutations.

The native endpoint pilot has 64 metadata-selected training source groups and 317 QA records; 16 other groups are isolated for inspection. Its videos span approximately6–11min. That preparation is an engineering cohort with weak native QA, not verified delayed-memory supervision. No dev/reserved QA belongs in this flow. Native source records must be adapted to question tail tokens and full answer IDs without inventing earlier cutoffs, evidence times or answer-dependent writes. Core data validation/actual PTS and native prompt packing remain caller responsibilities.

Matched training arms must share source/question order, initialization, trainable layers, update count, optimizer and declared retention/compute constraints. Equal retained visual steps do not establish equal total KV bytes. A later writer can use separately defined offline utility labels, but is not implemented here. Current-perception preservation and official benchmark evaluation remain necessary beyond this primitive.

Validation starts on hosted CI, with a real tiny Qwen3.5 hybrid LM and PEFT LoRA: cached-versus-uncached answer CE, actual LoRA gradients/updates, frozen base/detached prefix, live-cache isolation, source averaging, stale-cache rejection and failure semantics. No tests, lint or implementation execution on the authoring PC. Real4B/A100 gradient/cost verification and a complete training run remain pending; neither tiny-model tests nor cached/uncached agreement establishes memory quality.
